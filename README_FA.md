# SaKit: جعبه‌ابزار پردازش داده و کانفیگ در مرورگر

> ابزارهای سبک، سریع و کاملاً درون‌مرورگری برای رمزگذاری، رمزگشایی، تحلیل و تبدیل داده‌ها و فایل‌های کانفیگ.

SaKit یک جعبه‌ابزار وب مبتنی بر پردازش در سمت کلاینت (Client-Side) است که با هدف افزایش امنیت، سرعت و حذف وابستگی به سرورهای واسط توسعه یافته است. تمامی محاسبات، الگوریتم‌های رمزنگاری و پردازش فایل‌ها مستقیماً داخل مرورگر کاربر انجام می‌شوند.

- **آدرس اصلی اجرای آنلاین (GitHub Pages)**: [https://amirstillalive.github.io/SaKit/](https://amirstillalive.github.io/SaKit/)
- **آدرس آینه / پشتیبان (Cloudflare Pages / Vercel)**: قابل میزبانی بدون تغییر از ریشه پروژه.
- **[English Documentation](README.md)**

---

## معماری حریم خصوصی و پردازش محلی

1. **عدم ارسال داده‌های کاربر**: تمام ابزارهای اصلی تا حد امکان در سمت کاربر اجرا می‌شوند و داده‌های ورودی نباید برای پردازش عادی به backend ارسال شوند.
2. **محاسبات Base64**: با استفاده از موتور داخلی جاوااسکریپت مرورگر (`TextEncoder` و `TextDecoder`) و به صورت ۱۰۰٪ حافظه‌ای پردازش می‌شود.
3. **رمزگشایی کانفیگ‌های NPV**: پیاده‌سازی کامل ریاضیاتی الگوریتم‌های AES-128 CTR، ChaCha20-Poly1305 و جدول‌های وایت‌باکس در جاوااسکریپت.
4. **کش محلی و دارایی‌های استاتیک در برابر پردازش**:
   - برنامه از Service Worker و Web Manifest برای ذخیره دارایی‌ها استفاده می‌کند.
   - کدهای برنامه، فونت‌های وزیرمتن (Self-Hosted) و جدول‌های فشرده باینری (`gen2_tables.bin.z`) در نخستین مراجعه در حافظه مرورگر کش می‌شوند.
   - ادعای «کاملاً آفلاین» فقط برای قابلیت‌هایی مطرح است که build فعلی واقعاً بدون network قابل اجراست.

## ابزارهای موجود

### ۱. رمزگذاری و رمزگشایی Base64 (`/base64`)
- پشتیبانی کامل و استاندارد از UTF-8 و متون یونیکد (حفظ کامل خطوط فارسی، عربی، چینی و کاراکترهای خاص بدون خرابی).
- پشتیبانی همزمان از استانداردهای Base64 مرسوم و Base64URL با قابلیت ترمیم خودکار کاراکترهای پدینگ (`=`).
- امکان دریافت مستقیم فایل و تبدیل آن به رشته Base64.
- ابزارهای کمکی: کپی آنی، خروجی دانلود متنی، بارگذاری نمونه و دکمه چرخشی جابه‌جایی ورودی و خروجی.

### ۲. رمزگشایی کانفیگ‌های NPV Tunnel و NapsternetV (`/npv`)
- باز کردن فایل‌های قدیمی کانفیگ **`.npvt`** با جدول‌های ریاضیاتی White-Box.
- باز کردن بسته‌های **`.npvs` نسخه ۱ و ۵** بر پایه ChaCha20-Poly1305 و مشتق‌سازی کلید A16 KDK.
- سنتز و تولید خودکار لینک‌های اتصال استاندارد برای نرم‌افزارهای کلاینت:
  - **VLESS** (با پشتیبانی از Reality، XTLS Vision و TLS معمولی)
  - **VMess** (روی پروتکل‌های وب‌سوکت، TCP و ترافیک جعلی HTTP)
  - **Trojan** (با پشتیبانی از SNI و ALPN)
  - **Shadowsocks** (متدهای کلاسیک و استاندارد مدرن Shadowsocks 2022)
  - **SOCKS5 و HTTP Proxy**
- پردازش همزمان دسته‌ای (Batch) چندین فایل، جست‌وجوی زنده، فیلتر سریع بر اساس پروتکل و امکان دانلود فایل خام JSON کانفیگ‌ها.

## ناوبری و سیستم آدرس‌دهی (URLs)

| مسیر | ابزار مرتبط |
| :--- | :--- |
| `/` یا `/base64` | رمزگذاری و رمزگشایی Base64 |
| `/npv` | رمزگشایی کانفیگ‌های NPV Tunnel |

- **گیت‌هاب پیجز (GitHub Pages)**: بر روی زیرمسیر `/SaKit/` بالا می‌آید. پشتیبانی از ناوبری مستقیم با فایل خودکار `docs/404.html` پیاده‌سازی شده است.
- **کلادفلر پیجز و ورسل**: بر روی روت دامنه `/` مستقیماً با SPA Routing اجرا می‌شوند.
- **ناوبری درون اپلیکیشن**: منوی کشویی موبایل و سایدبار جمع‌شونده دسکتاپ امکان تغییر ابزار را بدون رفرش شدن صفحه و با ترنزیشن نرم فراهم می‌کنند.

## جدول سازگاری فرمت‌ها و وضعیت پشتیبانی

| ابزار | فرمت یا قابلیت | وضعیت | توضیحات |
| :--- | :--- | :--- | :--- |
| **Base64** | استاندارد Base64 | پشتیبانی می‌شود | مطابق استاندارد RFC 4648 §4 |
| **Base64** | فرمت Base64URL | پشتیبانی می‌شود | مطابق RFC 4648 §5، پدینگ ناقص خودکار اصلاح می‌شود |
| **Base64** | آپلود فایل باینری | پشتیبانی می‌شود | استخراج خودکار رشته کدگذاری‌شده از دیتا URL |
| **NPV** | فایل‌های `.npvt` | پشتیبانی می‌شود | رمزگذاری AES-128 در حالت CTR با جدول‌های عمومی White-box |
| **NPV** | فایل‌های `.npvs` نسخه ۱ | پشتیبانی می‌شود | پاکت با هدر JSON؛ متدهای `appKey` و `passphrase` |
| **NPV** | فایل‌های `.npvs` نسخه ۵ | پشتیبانی می‌شود | پاکت فشرده gen2؛ رمزنگاری ChaCha20-Poly1305 با بردارهای A16 KDK |
| **NPV** | فایل‌های `.npvs` نسخه ۲ تا ۴ یا بالاتر از ۵ | پشتیبانی نمی‌شود | ساختار ناشناخته/نامستند در طبیعت؛ برنامه شماره نسخه را صریحاً گزارش می‌کند |
| **NPV** | فایل‌های دارای قفل سخت‌افزاری خاص | پشتیبانی نمی‌شود | رمزنگاری متصل به کلید خصوصی ECDH کلاینت |

## راه‌اندازی و توسعه محلی

### پیش‌نیازها
- Node.js نسخه ۱۸ یا بالاتر
- مدیر بسته npm نسخه ۹ یا بالاتر

### دستورات خط فرمان
```bash
# دریافت مخزن
git clone https://github.com/AmirStillAlive/SaKit.git
cd SaKit

# نصب پکیج‌ها
npm install

# اجرای سرور توسعه محلی
npm run dev

# ساخت نسخه نهایی پروداکشن برای GitHub Pages (پوشه docs/)
npm run build

# پیش‌نمایش نسخه بیلد شده
npm run preview
```

## تست‌ها و بررسی کیفیت

```bash
# اجرای تمامی تست‌های بردار و پاریتی رمزنگاری
npm test

# اجرای تست مرورگر واقعی سرتاسری (با پروتکل Chrome DevTools)
npm run test:e2e
```

- **`test/links.test.mjs`**: ۶۳ بررسی صحت ساخت لینک‌های انواع پروتکل‌های پراکسی شامل قالب‌بندی براکت IPv6 و کانفیگ‌های v2ray.
- **`test/npvs-gen2.mjs`**: راستی‌آزمایی بردارها و ریاضیات نسخه ۵ و انطباق کامل خروجی با پایتون.
- **`test/npvs-parity.mjs`**: آزمون KDF و برابری بایت به بایت رمزگشایی در جاوااسکریپت و پایتون.
- **`test/browser-e2e.mjs`**: باز کردن مرورگر کروم، تعامل با کلیدها و آپلود واقعی فایل.

## نحوه انتشار (Deployment)

### استقرار روی GitHub Pages
پروژه از دایرکتوری `docs/` در شاخه `main` استفاده می‌کند:
1. دستور `npm run build` را اجرا کنید.
2. در تنظیمات مخزن گیت‌هاب (بخش Settings -> Pages)، شاخه را `main` و مسیر را `/docs` قرار دهید.

### استقرار روی Cloudflare Pages و Vercel
- **Cloudflare Pages**: دستور بیلد `npm run build` و دایرکتوری خروجی `docs`. سازگار با SPA Routing.
- **Vercel**: دایرکتوری خروجی را `docs` تنظیم کنید.

## نکات امنیتی و حریم خصوصی

- ابزار NPV با هدف پژوهش امنیتی، بازبینی پیکربندی‌های خود کاربر و بررسی ساختار و محتوای فایل‌های کانفیگ ارائه شده است.
- از قرار دادن رمزهای عبور واقعی، کلیدهای خصوصی، UUIDها یا سایر credentialهای حساس در Issues، Pull Requests، نمونه‌های عمومی یا مخازن عمومی خودداری کنید.
- پردازش فایل‌ها و داده‌های ورودی درون مرورگر انجام می‌شود و برنامه برای decrypt معمولی به backend نیاز ندارد.
- استفاده از یک کانفیگ decoded در یک client یا سرویس دیگر می‌تواند باعث برقراری اتصال به endpointهایی شود که داخل همان کانفیگ تعریف شده‌اند. پیش از استفاده، آدرس سرورها و سایر تنظیمات شبکه را بررسی کنید.
- ادعای «کاملاً آفلاین» فقط برای قابلیت‌هایی مطرح شود که build فعلی واقعاً بدون network قابل اجراست. برای قابلیت‌هایی که asset آنها در زمان اجرا به‌صورت lazy-load دریافت می‌شود، این موضوع باید صریحاً مستند شود.
